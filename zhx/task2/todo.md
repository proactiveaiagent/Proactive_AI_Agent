## 二、范围澄清（09-12 / 09-23 会议）

1. 7 层记忆模型**均围绕用户画像**展开，本次重点 = 构建基础架构 + 实现增删改查流程，而非仅 layer6 局部优化。
2. 属性统一结构：所有属性统一带**置信度 / 时间戳 / 最后使用时间**等字段（已落地的 AttrValue）。
3. 遗忘机制**按属性类型差异化**（三类，09-23 会议确认）：
   - **身份类**（如性别/姓名）：长久不衰减的记忆；
   - **经历类**（如上学阶段）：按缓慢衰减机制处理；
   - **时效类**（如过期优惠券）：到达设定时间直接遗忘。
   - 目标：Agent 能根据属性类型**自主判断**合理的衰减策略。
4. 文档规范：工作文档需**摒弃日报周报式概括**，改成「说明书 + 论文」形式，具体记录设计原理、代码位置、修改说明（见 `report.md`）。
5. 代码规范：之后的代码与产出**直接放主目录对应位置**（如 `scripts/memory/`），不再放 `zhx/` 下。
6. **双阶段处理流程**（09-23 会议新增）：
   - **短期记忆（闪存）**：白天实时快速存储与提取，为 Agent 提供上下文，场景结束后即可删除；
   - **长期记忆（整理）**：夜间对全天数据做总结、关联分析并更新用户画像，执行压缩合并控制摄入总量。
7. **非英文文本处理**（09-23 会议新增）：记忆存储时调用 LLM 翻译为英文统一存储，后台离线执行，不影响检索速度。
8. **多模态数据写入链路**（09-23 会议确认）：新的一天接收视频处理后，基于时间和计数器生成唯一 ID 写入 Layer1 临时记忆，随后根据地点和活动一致性分流至 Layer2（同场景）/ Layer3（当日记忆，最多 1000 条）/ Layer7（永久记忆）。
