## 测量口径

1. **记忆检索相关性**按 09-04 评测定稿，使用 `PersonMemory.query()` 对 `queries.json` 的 40 个查询统计 Precision@1/3/5/10、MRR@10 与 Hit@5。临时测试库使用 EgoLife 原始场景/动作文本及其 ground-truth 分类标签，ground-truth 只用于隔离评估记忆检索和六维索引；不会写入产品记忆或用于 Qwen 感知。
2. **容量**通过真实 `PersonMemory.add()` 结构生成短期 60 条与长期 1450 条临时库，保留全部 moments 和索引，不写视频或另存 ground-truth。以大样本的 3,005.79 B/moment 粗略线性外推，100 GiB 约可容纳 35.7M 条；短样本 3,968.30 B/moment，保守按它外推约 27.1M 条。外推用于规模估计，不代替长期运行实测。
3. **检索延迟**在 cxr25 本机用同一 40 查询集重复 20 次测量同步 CPU 路径，包含 `PersonMemory.query()` 的 JSON 字段匹配，不包含视频感知、Qwen 推理或网络调用。
4. **Qwen 感知评测**单独逐视频比较视觉/语言模型输出与自动标注的五个维度。短期 60 条：人物 P/R/F1 = 96.4%/94.9%/95.6%；地点 F1 6.2%、活动 F1 0%、环境 F1 7.8%、物品 F1 13.9%。这些低值主要反映标注本体不对齐/覆盖不足：`activity_gt` 是“操作物品/社交”等中文动作规则标签，而模型输出是 cooking/meeting 等自由语义；`environments_gt` 词典实际是 table/window/door 等局部物体，模型环境字段则是 indoor/room 等场景描述；location 标注覆盖也很稀疏。不能把该组 F1 当成记忆检索准确率，也不能据此声称模型在这些维度达到 95%。09-27 起采用视频 + 转写的独立 AI 语义复核，当前结果见补充评测；人工评审不再是前置条件。

长期测试集共有 1450 条标注行，但经验证是 725 个唯一视频片段；每对 _en/_cn 行在 video、start_time、end_time 和 transcript 上完全相同。评测按唯一输入生成一次 Qwen 结果，并分别与两行各自的 ground-truth 对比；日夜端到端记忆写入也按唯一输入去重，避免同一片段被重复记成两条事件。最终评测按 1450 条标签样本、725 个唯一输入统计，共享结果 725 条；725 个唯一事件单独写入日夜链路。
